# Урок 1. Введение в SQL и реляционные базы данных

## 1. Зачем нужен SQL

До сих пор данные, с которыми ты работала в Python, жили в памяти программы: списки, словари, объекты. Это удобно, пока:

- данных немного и они помещаются в память;
- программа работает в одном экземпляре и не нужно беспокоиться, что кто-то ещё одновременно читает/меняет те же данные;
- данные не обязаны переживать перезапуск программы.

Естественный следующий шаг, который приходит в голову — сохранять данные в обычные файлы: CSV, JSON, просто текст. Это действительно решает проблему "данные не переживают перезапуск", но создаёт новые проблемы:

- **поиск** — чтобы найти нужную строку, нужно прочитать и разобрать весь файл целиком, построчно; индексов нет;
- **одновременный доступ** — если два процесса одновременно пишут в один файл, легко получить повреждённые или потерянные данные;
- **целостность данных** — ничего не мешает записать строку с "неправильным" набором полей или неверным типом — формат файла сам по себе ничего не проверяет;
- **надёжность записи** — если программа упадёт посередине записи файла, можно получить файл в наполовину записанном, неконсистентном состоянии;
- **разбор данных** — формат нужно самостоятельно парсить и сериализовать, а значит, самостоятельно же писать и отлаживать код для этого.

Плоские файлы отлично работают для маленьких задач и одноразовых скриптов, но не масштабируются. Как только любое из условий выше (объём данных, параллельный доступ, надёжность) становится важным — нужна **база данных**: внешнее надёжное хранилище, которое умеет работать с данными, которые не помещаются в память, переживать перезапуски, корректно обслуживать несколько процессов одновременно и гарантировать целостность данных.

**SQL (Structured Query Language)** — язык для работы с реляционными базами данных: описания структуры данных, чтения, изменения и удаления.

## 2. Декларативность — главный сдвиг мышления

Python — императивный язык: ты описываешь *последовательность действий* (цикл, условие, присваивание), которая приводит к результату.

```python
result = []
for student in students:
    if student["grade"] >= 4:
        result.append(student["name"])
```

SQL — декларативный язык: ты описываешь **что** хочешь получить, а **как** это сделать — решает сама СУБД (система управления базами данных, database engine).

```sql
SELECT name FROM students WHERE grade >= 4;
```

Это не просто другой синтаксис — это другой способ мышления о задаче. С SQL ты почти никогда не пишешь "цикл по строкам" — ты описываешь условие, которому должен соответствовать результат.

## 3. Реляционная модель

Реляционная БД организована как набор **таблиц**.

| Понятие в реляционной модели | Аналог в Python |
|---|---|
| Таблица (table) | список словарей с одинаковыми ключами / DataFrame |
| Строка (row, record) | один словарь / одна запись |
| Столбец (column, field) | ключ словаря + тип значения |
| Схема (schema) | заранее описанная структура: какие столбцы есть и какого типа |

Главное отличие от списка словарей в Python: у таблицы есть **строго описанная схема**. Нельзя просто взять и добавить строку с произвольным набором полей — все строки одной таблицы обязаны соответствовать одной структуре.

### Первичный ключ (PRIMARY KEY)

Каждой строке в таблице обычно нужен уникальный идентификатор — **первичный ключ**. Это гарантирует, что на строку можно однозначно сослаться, даже если остальные данные (имя, дата) могут повторяться у разных записей.

### NULL — это не 0 и не пустая строка

`NULL` означает **отсутствие значения**, а не "значение по умолчанию". Это частый источник ошибок: `NULL = NULL` в SQL не возвращает `true` — результат такого сравнения тоже `NULL` ("неизвестно"). Для проверки на отсутствие значения используется отдельный синтаксис: `IS NULL` / `IS NOT NULL`.

## 4. SQLite vs PostgreSQL: почему начинаем с SQLite

| | SQLite | PostgreSQL |
|---|---|---|
| Архитектура | embedded — вся БД это один файл, отдельного сервера нет | client-server — отдельный процесс, к которому подключаются клиенты |
| Установка | не нужна, уже встроена в Python (`sqlite3`) | нужно установить и настроить сервер |
| Типизация | гибкая (type affinity) | строгая, много типов данных |
| Конкурентный доступ | ограниченный | полноценная поддержка множества подключений |
| Права доступа, роли | нет | есть (пользователи, роли, права) |
| Когда используется в реальности | мобильные приложения, локальные инструменты, прототипирование | веб-приложения, сервисы, production-системы |

Начинаем с SQLite, потому что это ноль настройки — можно сразу перейти к сути языка. Все базовые концепции (таблицы, SQL-синтаксис, ключи) одинаковы для обоих движков. Дальше в курсе перейдём на PostgreSQL, где эти же концепции заработают "по-настоящему": с сервером, правами доступа и более строгой типизацией.

## 5. Описание структуры: CREATE TABLE

```sql
CREATE TABLE students (
    id    INTEGER PRIMARY KEY,
    name  TEXT NOT NULL,
    grade REAL
);
```

- `INTEGER PRIMARY KEY` — столбец `id` — первичный ключ.
- `TEXT NOT NULL` — столбец `name` обязателен, не может быть `NULL`.
- `REAL` — число с плавающей точкой для среднего балла.

## 6. Первые запросы — SELECT

Базовая форма запроса на чтение данных:

```sql
SELECT столбцы FROM таблица WHERE условие ORDER BY столбец LIMIT N;
```

| Оператор | Назначение | Пример |
|---|---|---|
| `SELECT * FROM t` | все столбцы всех строк | `SELECT * FROM students;` |
| `SELECT a, b FROM t` | только нужные столбцы | `SELECT name, grade FROM students;` |
| `WHERE` | фильтрация строк | `SELECT * FROM students WHERE grade >= 4;` |
| `ORDER BY ... ASC/DESC` | сортировка | `SELECT * FROM students ORDER BY grade DESC;` |
| `LIMIT N` | ограничение количества строк | `SELECT * FROM students LIMIT 5;` |

Операторы сравнения в `WHERE`: `=`, `!=` (или `<>`), `>`, `<`, `>=`, `<=`, а также `AND`, `OR`, `BETWEEN`, `IN`, `LIKE` (поиск по шаблону в тексте).

## 7. Агрегатные функции (вводный обзор)

Агрегатные функции сворачивают множество строк в одно значение:

```sql
SELECT COUNT(*) FROM students;        -- количество строк
SELECT AVG(grade) FROM students;      -- среднее значение
SELECT MAX(grade), MIN(grade) FROM students;
SELECT SUM(grade) FROM students;
```

Группировку по категориям (`GROUP BY`) разберём на следующем занятии — сегодня достаточно увидеть, что такие функции существуют.

## 8. Мостик к Python

Тот же запрос можно выполнить прямо из Python через встроенный модуль `sqlite3`:

```python
import sqlite3

conn = sqlite3.connect("school.db")
cursor = conn.cursor()
cursor.execute("SELECT name FROM students WHERE grade >= 4;")
for row in cursor.fetchall():
    print(row)
conn.close()
```

SQL не живёт в отдельном мире — это инструмент, который дальше будет использоваться прямо из кода.
